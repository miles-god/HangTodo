# HangTodo 第一版验证记录

## 已验证

- 新建默认分类为“工作”，默认象限为“重要且紧急”。
- 实际界面完成新建、备注保存、正文编辑、修改分类和象限。
- 四象限筛选及分类计数正确，保存后切换到对应分类。
- 实际界面完成任务、查看已完成、重新打开、即时撤销。
- 重启应用后仍能读取已完成任务，重新打开保留原内容及分类、象限。
- 自定义分类新增、重命名；工作分类在界面中保留。
- 15 项任务通过底部分页访问到最后一项，全部保留。
- Swift 数据测试覆盖分类删除后的任务迁移、任务恢复、排序、过滤及持久化。
- 存储失败不发布更改，无法读取的文件不会被覆盖；撤销遇到存储错误也可重试。
- 长绳滚动范围、任务定位和任务数量减少后的边界已覆盖。
- arm64 / x86_64 通用应用构建与 ad-hoc 签名验证。

## 验证范围

界面验证在当前 Apple silicon Mac 上进行。Intel 仅完成构建，触控板与鼠标滚动手势、多屏和全屏交互尚未实测。界面自动化的滚动接口对 NSPanel 返回 `AXError.notImplemented`，因此长绳通过底部箭头验证。

测试用任务存档位于忽略版本控制的 `build/verification/`。第一版验证曾使用空存档；后续验证使用独立 bundle 和任务文件，不覆盖用户存档。

## 拖拽与计数更新

- 13 项测试通过，覆盖持久化排序、完成后恢复顺序、跨象限/分类/完成状态迁移、无效落点和存储失败。
- 卡片的勾选框与操作菜单命中区域独立于拖动区域，已通过原生视图命中测试。
- 接近分类时的平滑放大、取消拖拽后的状态清理已覆盖。
- 隔离验证应用中，保持已完成页打开时恢复任务，重要且紧急计数立即从 3 增至 4，已完成立即从 1 减至 0。
- 实际界面确认分类栏展开和鼠标靠近的放大反馈。
- 自动化工具的 macOS 拖拽接口返回 `AXError.notImplemented`，因此无法自动实测完整鼠标拖放手势；拖放后的数据行为已通过测试。
- UI 验证使用独立 bundle 和 `build/verification/drag-tasks.json`，未修改用户的任务数据。

## 显示、卡片、设置和单实例更新（2026-10-12）

- 22 项测试通过，包括空白与控件点击判断、同应用内窗口切换、边缘停留/重复/方向反转、500 项任务的可见范围和完整可达性、内容高度及超长备注、各卡片独立运动、默认中文及设置持久化、仅设置/退出的菜单、排他进程锁。
- 移除了鼠标离开后的自动收起计时。全局和本地点击共用控件边界，透明空白不再被整个工具栏或底栏误当成控件。
- 在独立 `app.hangtodo.uivalidation` 应用中确认设置集中显示，切换 English 后设置标题、配置、分类管理和晾衣绳立即更新；自定义“生活”和任务内容保持原文。
- 实际界面确认无备注的标题卡片约 50 点高；一行、三行、自然换行和十二行备注逐渐增高，多行内容完整显示。
- 500 项隔离任务实际出现右端连续自动翻页；渲染数量保持为当前屏幕附近的少量卡片。
- 从没有可见窗口的状态直接运行第二个可执行文件，第二进程退出码 0，原进程 PID 不变，晾衣绳重新出现。
- 本轮 arm64 / x86_64 通用构建与签名验证通过；用户任务文件 SHA256 在验证前后相同。
- UI 验证存档为 `build/verification/layout-tasks.json`。设置验证用 DEBUG 参数 `--ui-test-settings`；正式构建不包含此入口。
- 空白坐标点击与完整鼠标拖拽的自动化接口对 NSPanel 可能返回 `AXError.notImplemented`；这两种手势的事件判断和数据逻辑已测试，仍需手动交互确认。多屏、全屏和 Intel 实际交互未实测。

## 原生拖放接收与点击翻页更新（2026-10-12）

- 确认快捷键原本就按当前展开状态切换，保留原逻辑。
- 用外层 AppKit 接收视图替换 SwiftUI `onDrop`，与原生拖动来源使用同一个私有剪贴板类型；落点使用窗口坐标转换到绳子的顶部坐标，覆盖象限、分类、已完成和卡片排序。
- 25 项测试通过。新增原生接收回调测试使用真实 `NSPasteboardItem` 和窗口坐标，验证跨象限保存/重读、实时计数、分类迁移、完成/恢复、卡片两侧排序，以及无效 ID、操作类型和空白落点拒绝。
- 实际 NSHostingView 的象限按钮坐标与原生落点联动测试通过；命中路径中的第一个匹配拖放类型的接收视图是 AppKit 接收端，并成功改变象限。
- 删除悬停与拖动时的边缘自动翻页计时逻辑。左右箭头点击翻页，达到首尾后禁用。
- 删除底部常驻“待办 · x 项”和完成数量；保留操作后的短暂撤销提示。
- 独立 `app.hangtodo.dropcheck` 应用中，18 项任务通过右箭头两次到达第 18 项，最后一页右箭头禁用；通过左箭头返回后可再次前进。实际截图确认底部计数消失。
- 验证存档 `build/verification/click-paging-tasks.json` 与用户存档分离。
- 完整鼠标拖拽自动化仍返回 `AXError.notImplemented`，原生接收回调已验证，真实鼠标手势仍需手动确认。

## 快捷键、菜单关闭与 Apple silicon 构建（2026-10-12）

- 默认快捷键改为 Option + T；已有自定义快捷键保持不变。
- 修复录制窗口、重复注册及重载偏好设置的问题。新组合注册成功后才保存；无法注册时恢复原快捷键并显示中英提示。
- 独立 `app.hangtodo.shortcutcheck` 应用实际通过录制窗口修改为 Option + R，设置立即更新；退出并重新启动后仍显示 Option + R，启动没有注册错误提示。
- 菜单打开状态独立于晾衣绳显示状态；外部鼠标点击、同应用普通窗口点击及切换应用均主动取消菜单跟踪，菜单自身点击保留正常选择行为。
- 31 项测试通过，包括 Option + T 默认值、自定义快捷键/禁用设置重读、数字偏好兼容、Option 键录制和原生菜单取消回调。
- 构建脚本只生成 arm64 可执行文件，不再构建或合并 x86_64。此前的通用版本验证记录仅对应历史构建。
- Release 构建成功，`lipo -archs` 输出仅 `arm64`，严格签名验证通过。新版正式应用实际启动并显示原有两项待办；用户任务文件 SHA256 验证前后相同。
- 自动化按键无法确认 Carbon 全局热键的实际触发；菜单栏点击外部区域也未完成端到端鼠标验证。这些实际手势仍需人工确认，录制/重启持久化和菜单取消逻辑已分别验证。
